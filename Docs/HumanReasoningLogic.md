# CatPuzzle\_人类推理方法体系总结

CatPuzzle 人类推理方法体系总结

*用于主线关卡设计、Logical Solver、Hint 系统与每日挑战的推理规则框架*

**核心目标：**不是仅判断“有没有唯一解”，而是描述玩家如何在不依赖盲猜的情况下，一步一步从规则推出答案，并据此构建循序渐进的难度体系。

# 1\. 游戏约束与推理基础

- 棋盘为可变大小的 N×N 方格。
- 每一行恰好有 1 只猫。
- 每一列恰好有 1 只猫。
- 每一种区域恰好有 1 只猫；区域是分组属性，不要求连通。
- 任意两只猫不能处于 8 邻域相邻位置。

**推理的统一视角：** 行、列、区域都可以抽象为 Exactly\-One Constraint（“这个集合中最终恰好有一只猫”）。大多数高级推理，本质上都是这些约束之间的候选占位、锁定、冲突与传递。

# 2\. 第一层：基础确定性推理

**行唯一候选（Row Single）：**某一行还没有猫，且只剩一个候选格，则该格必为猫。

**列唯一候选（Column Single）：**某一列只剩一个候选格，则该格必为猫。

**区域唯一候选（Region Single）：**某种区域只剩一个候选格，则该格必为猫。

**已确定猫的直接传播：**确定一只猫后，排除同行、同列、同色以及 8 邻域内的所有其他候选。

# 3\. 第二层：锁定（Locking）与 Hall Set

## 3\.1 单对象锁定

**区域 \-\> 行锁定：若某区域的所有剩余候选都在同一行，则该行的猫一定属于该区域，因此该行其他区域候选全部排除。**

**区域 \-\> 列锁定：若某区域的所有候选都在同一列，则该列其他区域候选全部排除。**

**行 \-\> 区域锁定：若某一行的所有候选都只属于一种区域，则该区域必在此行，因此该区域在其他行中的候选全部排除。**

**列 \-\> 区域锁定：与上一条完全对称。**

## 3\.2 Locked Pair / Triple / K\<\-\>K

**核心规则：**若 K 个 Exactly\-One Constraints 的全部候选只落在 K 个目标约束中，则这 K 个目标必被它们完全占满，目标中其他候选可排除。这是鸽巢原理 / Hall 定理在本游戏中的直接应用。

**2 区域 \<\-\> 2 行：区域 A、B 只可能出现在 Row2、Row5 \-\> Row2/Row5 必由 A/B 占据 \-\> 两行内其他区域排除。**

**2 行 \<\-\> 2 区域（反向）：Row2、Row5 的候选只涉及 A、B \-\> A/B 必属于这两行 \-\> A/B 在其他行排除。**

**2 行 \<\-\> 2 列：Row2、Row5 只能使用 Column3、Column6 \-\> 其他行不能再使用 C3/C6。**

**2 区域 \<\-\> 2 列：区域 A、B 只可能在 C2/C5 \-\> C2/C5 内其他区域排除。**

**3\<\-\>3 / Triple：同理推广到 3 个区域、3 行，或 3 行、3 列等。**

**统一抽象： Row\<\-\>Column、Row\<\-\>Region、Column\<\-\>Region 三组关系都可以用同一个 Hall Set 引擎处理，而不需要为每种组合写特例。**

# 4\. 第三层：候选集合产生的“共同后果”

## 4\.1 Common Attack / 共同攻击区

**规则：**某个未确定的 Exactly\-One Constraint 最终一定会在其候选集合中选择一个位置。如果另一个候选格 X 与该集合中的每一个可能位置都冲突，则 X 必然不能是猫。

**典型例子：** Row3 的猫只可能在 C3 或 C4。若 R2C3 无论面对 R3C3 还是 R3C4 都会冲突，则 R2C3 可以直接排除。

**价值：**它利用了“位置尚未确定，但某些后果已经确定”的思想，是 CatPuzzle 相比普通数独更有空间感的一类特色推理。

## 4\.2 Strong Link / 强链接

**定义：**某个 Exactly\-One Constraint 只剩两个候选 A/B 时，A 与 B 构成强链接——二者中恰好一个是猫。

**第一阶段可用推理：**如果某候选 X 同时与 A 和 B 冲突，则无论最终选择 A 还是 B，X 都不可能是猫，因此可直接排除。

**后续扩展：**强链接还可形成链式推理、双分支共同结论、Alternating Inference Chain 等，但这些应放到更高难度或每日挑战阶段。

# 5\. 第四层：组合与链式推理

**邻接夹击 / Sandwich：**上下两行已知猫或强候选带来的邻接禁区叠加，可能把中间行压缩到唯一候选。

**锁定关系传递：例如 A/B \<\-\> Row2/Row5，同时 Row2/Row5 \<\-\> Column1/Column4，则区域、行、列三层锁定可连续传播。**

**邻接 \-\> 候选压缩 \-\> Hall Set：先由邻接排除若干候选，再形成 Pair/Triple 锁定，随后继续排除并产生 Single。**

**Almost Locked Set：**K 个约束暂时落在 K\+1 个目标中，只差一个排除即可形成真正 Hall Set；适合作为高级推理链的中间结构。

# 6\. 第五层：分支共同结论与反证

**双分支共同结论：**若 A/B 二选一，而 A 分支和 B 分支都会推出 D 必为猫，则不需要知道 A/B 哪个成立，也能直接确定 D。

**双分支共同排除：**若 A 为猫会排除 X，B 为猫也会排除 X，则 X 必然排除。

**Hall deficiency 反证：**假设某候选成立后，导致 K 个必须放置的约束只剩 K\-1 个槽位，则违反鸽巢原理，原假设不成立。

**有限假设 / Contradiction：**每日挑战允许假设某候选为猫，进行有限深度确定性传播；若产生矛盾，则反证该候选。

# 7\. 主线与每日挑战的边界

| 内容类型             | 允许的推理                                 | 假设深度        | 产品体验                                   |
| -------------------- | ------------------------------------------ | --------------- | ------------------------------------------ |
| 主线 Beginner / Easy | Single、直接传播                           | 0               | 直接、清晰、快速建立规则感                 |
| 主线 Medium          | 基础锁定、Pair                             | 0               | 需要观察约束之间的关系                     |
| 主线 Hard / Expert   | Triple、Common Attack、Strong Link、锁定链 | 0               | 需要多步确定性推理，但不猜                 |
| Daily Challenge      | 全部确定性规则\+ 有限反证/假设             | 1，极少数可到 2 | 允许试探，但必须可解释，不能退化为盲目回溯 |

# 8\. 建议的人类推理难度层级

**Level 1 基础：**Row/Column/Region Single；确定猫后的行列区域与邻接排除。

**Level 2 初级组合：**区域锁行/列、行/列锁区域、Locked Pair。

**Level 3 中级：Locked Triple、Row\<\-\>Column Fish/Hall 结构、Common Attack。**

**Level 4 高级：**Strong Link 共同排除、多个 Locked Set 传递、邻接与 Hall Set 混合链。

**Level 5 Expert：**Almost Locked Set、较长的确定性推理链、双分支共同结论，但仍不做假设回溯。

**Challenge：**有限 assumption、contradiction、Hall deficiency、深度 1～2 的可解释反证。

# 9\. 对 Logical Solver 的统一建模建议

**建议底层只维护少数通用概念：**

- Exactly\-One Constraint：行、列、区域。
- Candidate：仍有可能放猫的格子。
- Conflict / Weak Conflict：两个位置不能同时为猫（同行、同列、同色、8 邻域）。
- Hall Set / Locked Set：K 个 exactly\-one 约束只能占 K 个目标。
- Strong Link：一个 exactly\-one 约束只剩两个候选。
- LogicalStep / LogicalReason：每一步必须可解释。

**核心原则：**不要为“2区域锁2行”“2行锁2列”等分别写规则；应让它们从统一约束模型中自然产生。这样 Hint、Difficulty Analyzer、Generator 与 Daily Challenge 都可以复用同一套推理语言。

# 10\. 当前开发优先级建议

1. 已实现/优先：Single、Propagation、Generalized Locked Pair/Triple、Common Attack、Strong Link 基础共同排除。
2. 下一批可研究：Almost Locked Set、锁定关系传递、Hall deficiency 检测、双分支共同结论。
3. 更后期：任意长度 Strong\-Link / Weak\-Link chain、AIC、复杂 forcing chain。
4. 每日挑战专属：有限 assumption depth 1～2 \+ contradiction，不允许无上限 backtracking。

# 11\. 关卡设计原则

- 唯一解只是最低门槛，不代表关卡质量。
- 正常主线必须能够通过确定性人类规则完成。
- 难度应来自推理层级、链条长度、约束交互，而不是增加盲猜。
- 关卡应循序渐进地引入新技巧：先让玩家学会一种，再要求组合使用。
- 每日挑战可以允许少量试探假设，但每个假设都应有明确逻辑目的，并能通过矛盾或共同结论收束。
- Difficulty Analyzer 的机器分数必须经过真人试玩校准，不能仅靠固定权重决定最终难度。

# 12\. 总结

**CatPuzzle 的人类推理体系可以概括为：**从 Single 开始，通过 Exactly\-One 约束的候选缩减，逐渐形成 Lock / Hall Set；再利用候选集合的共同冲突形成 Common Attack 和 Strong Link；更高层则让这些关系互相传递，最终进入有限分支、反证和 Hall deficiency。

**主线设计原则：**“越来越需要看得深”，而不是“越来越需要猜”。每日挑战则允许有限、可解释的假设，从而形成与主线不同的高难度体验。
